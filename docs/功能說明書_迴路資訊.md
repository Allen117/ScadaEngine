# 功能說明書：迴路資訊（空調水系統 / 電力 / 自來水 / 氣）

## 1. 功能概述

EMS navbar「迴路資訊」dropdown 底下的四個頁面，版面與操作完全一致，差別只在能源別：

| 頁面 | 路由 | 迴路來源 | 單位 | 圖表色 |
|------|------|----------|------|--------|
| 空調水系統 | `/ChilledWaterCircuitInfo` | `WaterCircuit` | RT·h | 冰藍青 `#00838f` |
| 電力 | `/ElectricityCircuitInfo` | `EnergyCircuit` | kWh | 綠 `#2e7d32` |
| 自來水 | `/WaterCircuitInfo` | `WaterMeterCircuit` | m³ | 藍 `#0277bd` |
| 氣 | `/GasCircuitInfo` | `GasMeterCircuit` | m³ | 橘 `#e65100` |

版面：**左欄迴路階層樹 + 右欄三張長條圖**（年／各月、月／各日、日／各時）。
點左樹任一節點 → 右邊三張圖同時換成該迴路的資料；日卡片每 60 秒自動刷新。
頁面高度由 JS `fitPageHeight()` 依視窗算，整頁不出現捲軸。

> - 2026-08-05 由原單一頁 `/CircuitInfo`（僅電力）拆成三頁；舊路由已移除，未保留 redirect。
> - 2026-08-21 新增第四頁「空調水系統迴路」（冷凍噸 RT·h），並排在 dropdown 第一項。

### 名詞區隔（重要）

「空調水系統」與「自來水」是**兩套完全獨立的體系**，只是中文都有「水」字：

| 體系 | 資料表 | 物理量 | 演算法 |
|------|--------|--------|--------|
| 空調水系統 | `WaterCircuit` / `WaterLeafHourly` | 冰水主機冷量 RT·h | RT 瞬時值 AVG × 1h 積分（預聚合）|
| 自來水 | `WaterMeterCircuit` / `WaterMeterLeafHourly` | 用水量 m³ | 累積式讀數 boundary 相減 |

2026-08-21 起全站顯示名稱一律用「**空調水系統**」與「**自來水**」拉開區別（識別字如表名 / 路由 / resx key 未改）。

## 2. 路由 & 權限

| 方法 | 路由 | 說明 | 認證 |
|------|------|------|------|
| GET | `/ChilledWaterCircuitInfo` | 空調水系統迴路 | 需登入 |
| GET | `/ElectricityCircuitInfo` | 電力迴路資訊 | 需登入 |
| GET | `/WaterCircuitInfo` | 自來水迴路資訊 | 需登入 |
| GET | `/GasCircuitInfo` | 氣迴路資訊 | 需登入 |

- 四頁各自登錄於 `PermissionService.ConfigurablePages`，可在 `/AccountSetting` **逐頁**勾選
  （廠務只給水、能源組只給電之類的分授權）。
- 四頁皆在 `PermissionService.EmsRoutes` 內 → 自動套 EMS 淡綠主題。
- Controller 內 `CanAccessPage()` 不過 → `Redirect("/EMS")`（直連也擋得住）。
- navbar dropdown 四項各自 `canAccess()` 過濾；四項全無權限時整個 dropdown 不顯示。

## 3. 資料來源 API

| 頁面 | 迴路樹 | 用量資料 |
|------|--------|----------|
| 空調水系統 | `GET /EMS/api/chilled-water-circuit-tree` | `GET /EMS/api/chilled-water-rth` |
| 電力 | `GET /EMS/api/circuit-tree` | `GET /EMS/api/circuit-energy` |
| 自來水 | `GET /EMS/api/water-circuit-tree` | `GET /EMS/api/water-usage` |
| 氣 | `GET /EMS/api/gas-circuit-tree` | `GET /EMS/api/gas-usage` |

四組用量 API 的查詢參數與回傳契約完全一致：

```
?circuitId={id}&granularity={month|day|hour}&pivot={2026 | 2026-08 | 2026-08-05}
→ { labels: string[], values: number[], hasWarning?: bool }
```

- `granularity` 語意：`month` = 一年看各月、`day` = 一個月看各日、`hour` = 一天看各時。
- **月檢視的起訖日各自吃自己的月結期別**（電費 `BillingPeriods` / 水費 `WaterBillingPeriods` /
  氣費 `GasBillingPeriods`，氣費含 `IsSkipped` 兩月一期），由後端 `ParsePivotAsync` /
  `ParseWaterPivotAsync` / `ParseGasPivotAsync` 吸收，前端不需要知道差異。
- ⚠️ **空調水系統是唯一例外 —— 走曆制 `ParseCalendarPivot()`，不吃任何月結期別**。
  理由：`RefrigerationTonReportService` 月粒度已固定為曆月（綁能源申報、且冷凍噸不是算錢的報表）；
  這裡若套期別，同一迴路在本頁與 `/RefrigerationTonReport` 會出現不同數字。
  四支解析函式刻意拆開而非加參數，讓「用錯期別」變成編譯期選錯函式，而不是靜默算錯。
- `hasWarning`：**空調水系統 / 自來水 / 氣才有**，代表區間內有葉子的資料不完整（表計或主機斷線）。電力 API 無此欄位。

## 4. 前端架構

四頁共用 `wwwroot/js/ems-circuit.js` 一支（IIFE），差異以 **`data-kind`** 表達：

```html
<div class="ems-circuit-page" data-kind="chilledwater">   <!-- chilledwater | electricity | water | gas -->
```

JS 內 `CONFIG` 表持有四組 `{ treeUrl, usageUrl, unit, fill, border }`，
`init()` 讀 `data-kind` 決定 `_cfg`，其餘邏輯（建樹、選節點、三張圖 fetch/render、60s 輪詢）完全共用。

**新增第五種能源時**：在 `CONFIG` 加一組 + 複製一份 View 改 `data-kind` 與標題文字即可，JS 邏輯不必動。

資料缺漏警示（空調水系統 / 自來水 / 氣）：View 在每張卡片 body 內放

```html
<div class="ems-circuit-warn small text-warning" data-warn="hour" style="display:none;">部分時段冰水主機資料不完整（可能斷線）</div>
```

JS `setWarn(granularity, isWarn)` 依該次 API 的 `hasWarning` 切換顯隱；電力頁沒有這些元素 → 自動 no-op。

**數值位數**：tooltip 一律 `toFixed(1)`（RT·h 全站統一一位小數，見 [架構.md](架構.md) §用電報表），
Y 軸刻度則依級距自動決定位數（避免小值整排顯示成 0）。

## 6. i18n

頁面本身**不在 i18n 範圍**（字串為 zh-TW 硬寫，同原 `/CircuitInfo`）；
只有 navbar 選單字走 `Views.Shared._Layout.{,en}.resx`：

| key | zh-TW | en |
|-----|-------|----|
| `layout.menu.circuit_info` | 迴路資訊 | Circuit Info |
| `layout.menu.chilled_water_circuit_info` | 空調水系統迴路 | Chilled Water Circuit |
| `layout.menu.electricity_circuit_info` | 電力迴路資訊 | Electricity Circuit Info |
| `layout.menu.water_circuit_info` | 自來水迴路資訊 | Water Meter Circuit Info |
| `layout.menu.gas_circuit_info` | 氣迴路資訊 | Gas Circuit Info |

後四個 key 同時被 **Ctrl+K 全站搜尋**（`GlobalSearchService.PageIndex`）當作搜尋結果顯示名，
因此用全名而非「空調水系統/電力/自來水/氣」短標 — 搜尋結果是扁平清單，沒有 dropdown 父層可依附。
搜尋索引四筆同樣走 `CanAccessPage()` 伺服器端過濾，無權限的頁面不會出現在結果中。

## 7. 已知限制

- 迴路樹預設選「第一個根節點」。水/氣體系設計上為單一根迴路（全廠），因此等同預設選全廠。
- 未建任何迴路時，樹為空、三張圖維持空白（不報錯）。
- 電力頁的已知加總語意限制（主錶綁 SID 又掛子迴路時會連自身一起加總）與 `/EnergyReport` 相同，
  詳見 [功能說明書_EMS頁面.md](功能說明書_EMS頁面.md) §7.5。
- **空調水系統頁無正負號概念**：`WaterCircuit` 表無 `Sign` 欄位，階層加總純正向，不能像電力迴路那樣做扣減。
- 空調水系統為 on-demand 計算（逐葉子查 `WaterLeafHourly`），選根節點 + 年粒度時查詢量最大
  （葉子數 × 8760 筆），與 `/RefrigerationTonReport` 同一量級。
