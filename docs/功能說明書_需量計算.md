# 功能說明書：需量計算服務（DemandCalculatorService）

**版本**：1.0.0
**日期**：2026-06-29
**模組**：ScadaEngine.Engine

---

## 一、功能概述

台電以 **15 分鐘固定窗口**計費需量（契約需量）。本功能在 Engine 端每分鐘計算一次「過去 15 分鐘的時間加權平均功率（kW）」（滾動窗口），讓值班人員即時掌握各電表迴路的當前需量趨勢，在接近契約需量時提早採取措施。

> ⚠️ 滾動窗口與台電固定窗口不對齊，無法保證不超約。本功能為監控/預警工具，**非計費工具**。

---

## 二、資料流

```
EnergyCircuit.DemandSID (DB 設定)
        ↓ 啟動時載入
DemandCalculatorService
        ↓ 每分鐘
HistoryData 表 (15min 窗口)  →  TWA 計算  →  DemandData 表
        ↓ 同時（2026-09-24 需量虛擬點位）
RealtimeDataModel（SID=DMD-{kWhSID}）三路發布：
  ├─ RealtimeDataStorageService → 記憶體快取 + LatestData（LogicFlow / 條件控制）
  ├─ HistoryDataStorageService  → HistoryData（歷史查詢頁）
  └─ MqttPublishService         → MQTT（警報引擎 / Web 即時）
```

---

## 三、啟用條件

- `EnergyCircuit` 表中的葉子節點 `DemandSID` 欄位**不為 NULL** 時，該迴路啟用需量計算。
- `DemandSID` 填寫對應功率點位的 SID（例如 Modbus 功率點 `196865-S2`、計算點 `CALC-S3`）。
- 同一個 SID 即使被多個 EnergyCircuit 行共用，也只計算一次（`DISTINCT` 去重）。

---

## 四、計算邏輯

### 4.1 執行頻率

- Engine 啟動後，先對齊到下一個整分鐘（xx:00:00）再開始計算，避免第一次計算到不完整的窗口。
- 之後每分鐘觸發一次（計算時刻 `T = DateTime.Now` 截到整分鐘）。

### 4.2 窗口定義

| 欄位 | 說明 |
|------|------|
| WindowStart | `T - 15 分鐘` |
| WindowEnd (= T) | 計算時刻（整分鐘） |

查詢 `HistoryData` 中 `Timestamp BETWEEN WindowStart AND T` 且 `Quality = 1` 的樣本，並依 Timestamp 升冪排序。

### 4.3 時間加權平均（TWA，step-hold 模型）

```
totalWeighted = 0, totalSeconds = 0
for i = 0 .. N-2:
    dt = points[i+1].Timestamp - points[i].Timestamp  (秒)
    totalWeighted += points[i].Value × dt
    totalSeconds  += dt

// 最後一段延伸到 windowEnd（T）
lastDt = T - points[N-1].Timestamp  (秒)
totalWeighted += points[N-1].Value × lastDt
totalSeconds  += lastDt

DemandKW = totalWeighted / totalSeconds
```

> 採 step-hold 模型的原因：Modbus 掉線補點、Engine 重啟等情況點距不均，若用簡單平均（SUM/COUNT）會使短點距資料過度影響結果。

### 4.4 資料品質判斷

| 條件 | DemandKW | Quality |
|------|----------|---------|
| Quality=1 樣本數 ≥ 5 | 時間加權平均值 | 1（Good） |
| Quality=1 樣本數 < 5 | 0 | 0（資料不足） |

## 五、資料庫設計

### DemandData 表

| 欄位 | 型別 | PK | 說明 |
|------|------|----|------|
| SID | nvarchar(100) | ✅ | 對應 EnergyCircuit.DemandSID |
| Timestamp | datetime | ✅ | 計算時刻（truncate 到整分鐘，local time） |
| DemandKW | float | | 15min 滑動 TWA 功率（kW）；Quality=0 時為 0 |
| WindowStart | datetime | | 窗口起點（= Timestamp - 15min） |
| SampleCount | int | | 窗口內 Quality=1 樣本數 |
| Quality | tinyint | | 1=Good, 0=資料不足（SampleCount < 5） |

- Clustered Index: (SID, Timestamp)
- 採 MERGE 寫入（同一分鐘重算可覆寫，不產生重複）

## 六、熱重載

`DemandCalculatorService` 提供公開方法 `ReloadDemandSidsAsync()`。

當 Web 端修改 `EnergyCircuit.DemandSID` 設定後，可透過 MQTT Reload Subscriber 呼叫此方法，讓 Engine 立即重新讀取最新的 DemandSID 清單，無需重啟服務。

> 目前 Web 端尚未發布 EnergyCircuit Reload MQTT 信號，`ReloadDemandSidsAsync()` 供未來擴充使用。

## 七之一、需量虛擬點位（2026-09-24）

需量原為「孤兒資料」——只寫 DemandData 專用表，條件控制（讀 LatestData）、LogicFlow（讀記憶體快取）、歷史查詢（讀 HistoryData）、警報引擎（訂 MQTT）全以 **SID 為 key** 的通用管線取值，接不到需量。本功能讓需量升格為虛擬點位，完全比照計算點（`CalculatedPointService`）的三路發布，**消費端零改動**。

### SID 格式與映射

| 項目 | 值 |
|------|-----|
| SID | `DMD-{kWhSID}`（例 `DMD-196865-S1`），與 `DemandData.SID` 一對一可逆推 |
| 名稱 | `{電表名} 需量`（電表名 = EnergyCircuit MIN(Name)；查無名稱時退 kWh SID） |
| 單位 | kW |
| Quality | 忠實透傳：DemandData Quality 1→`Good`、0→`Bad`（**Bad 時值為 0，不美化為 Good**，避免誤觸發下限/卸載邏輯） |
| Timestamp | 計算 tick（整分鐘） |
| coordinatorName | `需量`（MQTT payload 分群用） |

映射邏輯集中於 `DemandCalculatorService.ToRealtimePoint()`（有單元測試 `DemandRealtimePointTests` 鎖住）。

### 發布路徑（照抄計算點模式）

每分鐘 `CalculateAllAsync` 算完 UPSERT DemandData 後，同批結果組成 `RealtimeDataModel` 清單：

1. `HistoryDataStorageService.AddRealtimeDataBatch` → HistoryData（每分鐘 1 筆/SID）
2. `RealtimeDataStorageService.AddRealtimeDataBatch` → 記憶體快取 + LatestData（5 秒 flush）
3. `MqttPublishService.PublishRealtimeDataAsync` → MQTT（Retain=true，同計算點既有模式）

### 消費端

| 消費端 | 進入方式 |
|--------|----------|
| 條件控制 | 條件點下拉「需量點位」群（**控制點選單刻意排除** —— 需量唯讀不可寫） |
| LogicFlow | picker「需量點位」來源卡（output 節點隱藏，同計算點唯讀規則） |
| 警報設定 | 設備下拉「需量點位」→ 上限規則 → Line/Email/SMS 通知 |
| 歷史查詢 | 側欄「需量」桶（`data-sid-prefix="DMD-"`），趨勢/取樣間隔/Excel 匯出全可用 |
| Designer / 計算點 / EventLog picker | `/Designer/Points` 已含需量點群（Designer、計算點 picker 有專屬來源卡） |
| 即時數據頁 | MQTT 自動收進快取，依 coordinatorName「需量」分群顯示 |

### 雙軌並存

`DemandData` 表與 EMS 需量卡 / Designer `demand_kw` 迴路指標的專用查詢**原樣保留**（stale 判定、迴路遞迴加總語義不動）；虛擬點位是「多發一份」。既有 DemandData 歷史**不回填** HistoryData —— 上線後才開始累積（如需回填可跑一次性 SQL）。

- 15 分鐘滾動窗口與台電計費窗口（每整點 0/15/30/45 分）**不對齊**。
- 不加自動清理，DemandData 全量保留；未來依需求另行規劃清理策略。
