# 功能說明書：班別設定（/ShiftSetting）

對應標案規格 4-12「各點位數據依班別設定分段檢視」。定義工廠班別（早/中/晚班等），
供**電（/EnergyReport）、水（/WaterUsageReport）、氣（/GasUsageReport）三個用量報表**的
「**班別**」粒度分段檢視使用。

## 1. 功能概觀

- 班別 = 名稱 + **整點**起訖時間（可跨日）+ 適用星期（週一~週日勾選）
- 三報表粒度下拉多一個「班別」選項，配起訖日（含日）查詢：**每列 = 日期 × 班別**，含長條圖與 Excel 匯出
- 每日未被任何班次涵蓋的時段合併為一列「**非班別**」，使 Σ(各班 + 非班別) 可與日粒度對帳
- 不考慮國定假日（純看星期）；不支援 :30 等非整點交班（見 §5 設計取捨）

## 2. 儲存與資料結構

存 `SystemSettings` 一列 JSON（`SettingKey = 'shift_schedule'`），仿電費 TOU `electricity_tariff` 模式，
**不新增資料表**、DatabaseSchema.json 不需改。單一現行版本 — 改動即對所有歷史查詢回溯生效
（班別是查詢時的檢視切法，非計價依據，不需 TOU 那種 adoptions 生效時間軸）。

```json
{
  "shifts": [
    { "szName": "早班", "nStartHour": 8,  "nEndHour": 16, "weekdays": [1,2,3,4,5] },
    { "szName": "晚班", "nStartHour": 22, "nEndHour": 6,  "weekdays": [1,2,3,4,5] }
  ]
}
```

- `nStartHour` / `nEndHour`：0~23 整點；**訖 <= 起視為跨日**（22→6 = 至隔日 06:00）；訖 0 = 至當日 24:00（不吃隔日時數）
- `weekdays`：0=週日 .. 6=週六（對齊 .NET `DayOfWeek`）；UI 顯示順序為週一~週六、週日

## 3. 規則

### 3.1 驗證（儲存時整份檢查，`ShiftScheduleService.ValidateCore`）

- 名稱必填且唯一；時數 0~23 整點；起訖不可相同；適用星期至少勾一天
- **一週 168 小時時間軸上任兩班次不可重疊**（含跨日溢入隔日、週日晚班 wrap 週一）— 重疊會導致用量重複計算，直接擋下
- 空清單允許（= 清空班表）；清空後報表選班別粒度回 400 +「尚未設定班別」提示

### 3.2 展開與歸屬（`ShiftScheduleService.BuildBucketPlan`）

- **跨日班整段歸屬起始日**：週一 22:00~06:00 的用量（含週二凌晨段）記在週一晚班
- 查詢範圍**首日**凌晨若被「前一日跨日班」涵蓋 → 該段歸前一日、不列入本次結果；
  查詢範圍**末日**的跨日班會整段計入（含超出末日的凌晨段）— 班別歸屬優先於曆日切齊，
  因此範圍邊界有跨日班時，Σ班別 與「同範圍日粒度總量」會差首/末日的凌晨段（中間日恆一致）
- 非班別缺口可能多段不連續（班與班之間有空檔）→ 多個計算區間併回同一顯示列（`MergeByGroup`，stale 取 OR）
- 標籤：單日查詢不帶日期前綴；多日帶 `MM/dd`；跨年帶 `yyyy-MM-dd`

### 3.3 報表計算路徑（班界限整點的原因）

| 報表 | 資料路徑 | 班別 bucket 作法 |
|------|---------|----------------|
| 用電 | HistoryData 邊界值相減（on-demand） | 每班次一對 [起,訖) 邊界相減（計算核心本就吃任意 pair） |
| 用水 | `WaterMeterLeafHourly` 逐時預聚合 | HourStart 落入班次區間的列累加 |
| 用氣 | `GasMeterLeafHourly` 逐時預聚合 | 同上 |

水/氣預聚合表只有整點粒度 → **班界限整點**讓三報表全走現成路徑；
若未來要支援 07:30 交班，水/氣需另開原始資料路徑（複製 Engine 溢位/UnitScale 邏輯），成本高一個量級。

## 4. API 與檔案結構

| 方法 | 路由 | 說明 |
|------|------|------|
| GET | `/ShiftSetting` | 設定頁（需登入；EMS 淡綠主題、逐頁授權） |
| GET | `/ShiftSetting/api/config` | 整份班別設定 |
| POST | `/ShiftSetting/api/config` | 儲存整份（驗證失敗 400 + 已本地化訊息） |

```
ScadaEngine.Web/
├── Features/ShiftSetting/
│   ├── Controllers/ShiftSettingController.cs
│   ├── Models/ShiftSettingModels.cs       ← ShiftScheduleConfig / ShiftDefinition / ShiftBucketPlan
│   └── Views/Index.cshtml
├── Services/ShiftScheduleService.cs       ← 讀寫 + 驗證 + 展開器（三報表共用，static 純邏輯可測）
└── wwwroot/ css/shiftsetting.css、js/shiftsetting.js
```

三報表改動：各自 `XxxReportService.BuildBucketRangesAsync` 加 shift 分支（回傳 calcRanges + groupOf 對映）、
View 粒度下拉 + 起訖日控制項、JS `buildRequest` shift 分支、Excel 匯出器粒度名稱。
i18n：`Features.ShiftSetting.Views.Index.{,en}.resx`、`Services.ShiftScheduleService.{,en}.resx`（驗證訊息 + 非班別標籤）、
三報表 resx 加 `granularity.shift`、`Views.Shared._Layout` 加 `layout.menu.shift_setting`。

單元測試：`ScadaEngine.Tests/ShiftSchedule/ShiftScheduleServiceTests.cs`（驗證/展開/合併/缺口計算）。

## 5. 設計取捨

- **班別 = 第五種報表粒度**而非獨立頁面/切換鈕 — 複用既有粒度切換、查詢、匯出管線，UI 零新概念
- **限整點**：見 §3.3；工廠班表絕大多數整點交班，先出可上線版（2026-09-24 使用者定案）
- **不接國定假日**：純看星期（使用者定案）；未來要接可在展開器加「假日不排班/視同週日」開關 + `HolidayService.IsHolidayAsync`
- **無版本時間軸**：班表改動回溯套用所有歷史查詢；需要「歷史班表」時再升級 adoptions 模式
