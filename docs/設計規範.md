# 設計規範

本文件定義 ScadaEngine.Web 全站共用的視覺與互動規範。功能特定樣式（例如 LogicFlow 節點、能源報表圖表）若有偏離此規範的需求，請在對應功能說明書中註記原因。

新增/修改 `.cshtml`、`.css` 前先讀本檔。

---

## 框架與函式庫
- **CSS 框架**: Bootstrap 5.1.0（本地安裝）
- **圖示庫**: Font Awesome 6（`fas` 前綴）
- **圖表庫**: Chart.js + date-fns adapter
- **語系**: zh-TW（繁體中文）

## 元件模式

### 卡片
```html
<div class="card shadow-sm">
  <div class="card-header bg-dark text-white py-2">
    <h6 class="mb-0"><i class="fas fa-[icon] me-2"></i>標題</h6>
  </div>
  <div class="card-body p-0"><!-- 表格用 p-0，表單用 p-3 --></div>
  <div class="card-footer bg-light text-muted"><!-- 統計/時間戳 --></div>
</div>
```

### 表格
- 類別: `table table-striped table-hover table-bordered`
- 表頭: `thead class="table-dark"` 或 `table-light`
- 外層: `table-responsive` wrapper
- 表頭 sticky: `position: sticky; top: 0; z-index: 30`

### 側欄（設備清單）
- 寬度: `col-md-2`
- 使用 `list-group list-group-flush`
- Active: 左邊框 3px `#0d6efd` + 背景 `#e8f0fe`
- 子項: `ps-4` 縮排 + 背景 `#f8f9fa`

### 按鈕
- 格式: `<i class="fas fa-[icon]"></i> 文字`（圖示+文字，禁止只有圖示）
- Hover: `translateY(-1px)` 上浮
- Active: `translateY(1px)` 下壓

### 表單
- 標籤: `form-label fw-semibold` + 前置圖示
- 輸入: `form-control form-control-sm`
- 下拉: `form-select form-select-sm`
- 排列: `row g-3` + `col-md-*`

### Modal
- 標準結構: `.modal-header` + `.modal-body` + `.modal-footer`
- 取消: `btn btn-secondary`（左）、確認: `btn btn-primary`（右）

### 空狀態
```html
<div class="text-center text-muted py-4">
  <i class="fas fa-inbox fa-3x mb-2 d-block"></i>
  <div>尚無資料</div>
</div>
```

### 時間輸入（24 小時制，用 flatpickr）

**新增**任何 datetime / time 選擇控制項時**禁止**用原生 `<input type="datetime-local">` / `<input type="time">`：Chromium 在 zh-TW Windows 下會強制吃 OS locale 顯示「下午 01:34」，`lang="en-GB"` trick 對 datetime-local 已證實無效。改用 flatpickr + 共用 helper `window._fpInit`。

date-only（純日期、無時間）可繼續用原生 `<input type="date">` — 無 AM/PM 問題不必引入 flatpickr。

```html
<!-- View 頂端 -->
<link rel="stylesheet" href="~/lib/flatpickr/flatpickr.min.css" />

<!-- input 用 type="text" -->
<input type="text" id="dtStart" class="form-control" autocomplete="off" />

<!-- @section Scripts 依序載入 -->
<script src="~/lib/flatpickr/flatpickr.min.js"></script>
<script src="~/lib/flatpickr/zh-tw.js"></script>
<script src="~/js/flatpickr-init.js"></script>
<script src="~/js/myfeature.js"></script>
```

```js
// feature.js 內初始化（依 <html lang> 自動切 zh-TW / en locale，強制 time_24hr）
window._fpInit.datetime(document.getElementById('dtStart'));  // YYYY-MM-DD HH:mm
window._fpInit.time(document.getElementById('txtStartTime'));  // HH:mm

// 寫值要走 setDate，不能直接 .value = ...（picker 狀態不會同步）
dtStart._flatpickr.setDate(new Date(), true);
// 讀值照舊用 .value
var s = dtStart.value;
```

Razor 預設值輸出空白分隔格式對齊 flatpickr `Y-m-d H:i`：`Model.dt.ToString("yyyy-MM-dd HH:mm")`。後端 `DateTime.TryParse` 對 T / 空白分隔都吃，不需改 API。

## 色彩系統

### SCADA / EMS 雙主題

全站依路由分為兩套色系。`_Layout.cshtml` 偵測 `PermissionService.IsEmsRoute()` 自動掛 `body.ems-mode` class；`ems.css` 在該 class 下覆寫 navbar / footer / brand 與所有 Bootstrap primary 衍生 class（`.text-primary` / `.btn-primary` / `.bg-primary` / `.form-control:focus` / `.spinner-border.text-primary` / `.card-header.bg-primary`），以及樹狀清單 `#treeContainer .tree-node.active` 等共用元件。

**頁面寫法**：直接用 Bootstrap class，不要硬寫色號，色系切換交給 `ems.css` 自動處理。新增 EMS 子頁專屬色彩時用 `body.ems-mode .your-class` 覆寫，避免污染 SCADA 模式。**不要在 `.cshtml` inline 硬寫藍色色號（如 `style="color:#0d6efd"`），會破壞 EMS 模式切換。**

**新增 EMS 子頁掛載步驟**（自動套主題，不需在 View / Controller 手動切色）：

1. 路由加入 `PermissionService.EmsRoutes[]`（同時加 `ConfigurablePages` 給權限管理用）
2. `_Layout.cshtml` 偵測 `IsEmsRoute()` 自動掛 `body.ems-mode` class（既有機制，不用改）
3. `ems.css` 自動把 navbar / brand / footer 綠色化 + 覆寫 Bootstrap primary 衍生 class（見上）
4. navbar 加 nav-link（搭 i18n key `layout.menu.xxx`，走 `Views.Shared._Layout.{,en}.resx`）

- **資料**: `fa-calendar`（日期）、`fa-clock`（時間）、`fa-database`（資料庫）

### 兩條容易踩到的規則

**① 頁面標題圖示 = 該頁側欄選單的圖示**
`<h2>` 的圖示要與 `_Layout` 裡對應選單項用同一個 glyph，使用者才對得起來。
⚠️ 複製既有頁面當範本時**最容易漏改這一行** — 例：水表 / 氣表迴路設定曾整頁沿用電表的 `fa-sitemap`。
`fa-sitemap` 專指**電表**迴路設定（`/EnergyMeter`），水表用 `fa-faucet`、氣表用 `fa-gas-pump`。

**② 同一個下拉選單內不得出現重複 glyph**
`_Layout` 的「報表」「設定」兩個 dropdown（含各 submenu 群組標頭）各自不可撞號，
否則使用者在同一張清單上看到兩個一樣的符號無法區辨。新增選單項時先掃一遍該選單既有圖示。

### 下拉選單圖示對齊（已由 CSS 統一處理，不需逐項加 class）

Font Awesome 是字型圖示，各字符 advance width 本來就不同（`fa-tint` 窄、`fa-file-invoice-dollar` 寬），
直接排在文字前會讓每列文字左緣參差。`wwwroot/css/navbar-submenu.css` 已對
`.navbar .dropdown-menu .dropdown-item > .fas`（含 submenu 群組標頭）統一
`width: 1.25em` + `text-align: center` + `font-size: 1em`（等同 FA 的 `.fa-fw`）。

→ 新增選單項照現有寫法 `<i class="fas fa-xxx me-2">` 即可，**不必也不要**額外加 `fa-fw` / `fa-lg` / `fa-sm`
（`font-size: 1em` 會把 `fa-lg`、`fa-sm` 壓回去，避免有人單獨放大某一項造成大小不一）。

### 下拉選單寬度與 submenu 箭頭（同檔 CSS，勿改回 float）

- `.navbar .dropdown-menu` 設 `min-width: 13rem` —— Bootstrap 預設 10rem，中文標籤（「空調水系統」「卡片顯示設定」）
  加上固定寬圖示後幾乎貼滿，各列會擠成一團。比 13rem 長的標籤仍會自動撐開。
- submenu 群組標頭的展開箭頭 `::after` 用**絕對定位**貼右緣，**不可改回 `float: right`**：
  float 的箭頭是流內元素，內容剛好填滿 content box 時會整個掉到下一行，看起來像箭頭疊在文字底下
  （中文標籤與切英文後的長標籤都會踩到）。

### 數值顯示位數

能源類數值（kWh / RT·h）一律**小數一位、0 顯示為 `0.0`**、帶千分位；只收斂顯示層，計算與 API 維持全精度。
完整規則（涵蓋範圍、例外、Excel 格式）見 [功能說明書_能源管理.md](功能說明書_能源管理.md) §12。
