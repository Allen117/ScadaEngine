# 功能說明書 — 氣費設定、氣費月結週期與氣費報表

> 只做天然氣「**流動氣費**」分段累進（1 度 = 1 m³）；**不做基本費**、無 TOU / 季節、**不做熱值換算**。
> 用氣量來源見 [功能說明書_用氣報表.md](功能說明書_用氣報表.md)；跨模組總覽見 [架構.md](架構.md) §用氣報表與氣費計算。

## 1. 設計決策：on-demand，不建 GasCostHourly

電費需要逐時表（`ElectricityCostHourly`）是因為 TOU 每小時單價不同；氣費只有分段累進，**成本 = f(期別總量)**，逐時成本無物理意義。
因此氣費全部 on-demand：報表 / EMS 卡片當下由 `GasMeterLeafHourly` 加總期別用氣量再套級距，省掉一張表 + 一個背景服務 + 重算機制（同水費）。

## 2. 費率方案（/GasTariffSetting）

- 儲存：`SystemSettings.gas_tariff`（整份 JSON），結構 = 方案列表，每方案含 **生效日** + 級距陣列。
- Seed：`ScadaEngine.Web/Setting/gas-tariff-defaults.json` —
  **天然氣無全國統一費率**（依供氣事業合約而定），故 seed 刻意是**空白單一級距範本**：

| 級距（度） | 單價（元/度） |
|---|---|
| 1 以上 | 0 |

  首次進頁請依供氣事業合約帳單自行新增級距與單價。「還原預設範本」會回到這張空白表。
- **方案版本（生效日）**：計算某期氣費時依「期別**起日**」選用當時生效的方案（生效日 ≤ 起日中最新者；都不合則取最早方案）。改費率新增一版即可，**歷史期別氣費不被追溯改寫**。
- 驗證（`GasTariffService.ValidatePlan`）：第一級從 1 起、級距連續遞增、僅末級上限可為「以上」（null）、單價非負、生效日 yyyy-MM-dd。

### ⚠️ 級距與期別長度**完全解耦**（決策 7）

費率頁的級距是使用者**照帳單原樣填入**的數字。期別設定（含兩月一期）**不影響級距**，
系統**不做**任何依期別長度的自動換算，費率方案也**不含**「期別月數 / 倍率」欄位。

理由：兩者是各自獨立的輸入 — 期別決定「一期涵蓋哪些日子」，級距決定「一期總量怎麼計價」。
加倍率欄位等於讓系統去猜使用者填的是哪一種級距，多一個會被填錯又難以察覺的欄位。
→ **若設為兩月一期，請直接填「一期」的級距數字。**
此規則由 `GasCostServiceTests.級距與期別解耦_不做任何天數倍率換算` 鎖住。

## 3. 氣費月結週期（/GasBillingPeriodSetting）— 唯一與電/水不同的一頁

`GasBillingPeriods` 結構同 `BillingPeriods` / `WaterBillingPeriods`，但**多一個 `IsSkipped bit` 欄位**，
用來支援供氣事業常見的**兩月一期**抄表週期。電/水兩套期別表刻意不加此欄位。

### 3.1 兩層解析

`GasBillingPeriodService` 的期別解析分兩層：

| 層 | 說明 |
|----|------|
| **nominal（名目）** | 完全等同水費版推導：有非 skipped 自訂 row → 直接採用；否則起始 = 前一期結束 +1 天（往前追溯至最近一筆非 skipped 自訂 row 逐期級聯），結束 = 起始 + 1 個月 − 1 天；完全無自訂 row 時 = 自然月。**skipped 的 row 在這一層視同不存在** |
| **effective（生效）** | skipped 的期別不存在（回 null）；存在的期別**吸收**相鄰 skipped 期的日數 — 向後吸收同年緊接其後的連續 skipped 期；若本期之前（同年）所有期皆 skipped，則向前吸收至該年 1 月起始 |

由此自然得出兩條行為，**不需要任何鄰期改寫**：

- **刪除某期 = 其日數併入前一期**（前一期結束日往後延伸）
- **刪除該年第一期 = 由下一期向前吸收**（下一期起始日往前延伸）
  — 刻意不併進去年 12 月期：期別的年歸屬是「起始所在月份的年」，併過去會竄改去年帳單。

因此「刪除 / 復原」都只是**單一 row 的寫入或刪除**，不動任何鄰期，**完全可逆**。

### 3.2 操作與呈現

- 清單**只列實際存在的期別** — 刪掉 6 期後就只剩 6 列，每列各有自己的起訖日與天數。
  非自然月的列會在期別下方加一行完整區間標籤（如 `2026-01-01~02-28`）。
- 被刪除的期別收在清單下方「**已刪除的期別（可復原）**」摺疊區，按「復原」即拆回原狀。
- **操作流程（使用者只需一步）**：在 2 月列按「刪除此期」→ 系統自動把 1 月期變成 `1/01~2/28`，清單剩 11 列；
  依此刪掉 4/6/8/10/12 月即得 **6 列兩月一期**（全年日數合計仍為 365/366，無空窗無重疊）。
- 刪除前的確認框會明說併入哪一期、鄰期日期會變成什麼。
- 該年只剩一期時拒絕刪除（否則整年日數無人涵蓋），前端按鈕 disabled + 後端 `ArgumentException` 雙重擋。

### 3.3 API

| Endpoint | 說明 |
|---|---|
| `GET  /GasBillingPeriodSetting/api/list?year=` | 該年存在的期別 + 已刪除清單 |
| `POST /GasBillingPeriodSetting/api/save` | 自訂起訖（一律寫 `IsSkipped=0`，對已刪除期存檔等同復原） |
| `POST /GasBillingPeriodSetting/api/reset` | 還原推導預設（刪自訂 row，不影響已刪除狀態） |
| `POST /GasBillingPeriodSetting/api/skip` | **刪除此期**（寫 `IsSkipped=1`） |
| `POST /GasBillingPeriodSetting/api/unskip` | **復原此期**（刪掉 `IsSkipped=1` 的 row） |
| `GET  /GasBillingPeriodSetting/api/current` | 今天所屬期別（用氣報表日粒度預設起訖） |
| `GET  /GasBillingPeriodSetting/api/range` | 期別區間查詢（報表期別提示；已刪除期別不列） |

### 3.4 ⚠️ 維護注意

`GasBillingPeriodService` 因 `IsSkipped` 而**不再與電/水兩版結構全等**。
類別註解已標明差異點 — 日後若有人「照水版對稱修正」而移除 skipped 相關分支，兩月一期會直接失效。
規則由 `ScadaEngine.Tests/GasMeter/GasBillingPeriodServiceTests.cs` 鎖住
（含「刪 2 月 → 1 月變 1/01~2/28」「兩月一期全年恰 6 期、日數合計 365/366」「全年每一天恰落在一期內」「復原回原起訖」等斷言）。

## 4. 氣費計算（GasCostService）

- 計費週期走 **`GasBillingPeriods` 氣費期別**。與電費、水費期別**各自獨立**。
- 每迴路**獨立**對自身期別總用氣量套分段累進（無占比分攤；分段演算法同水費：`lower = nFrom-1`、`upper = nTo ?? ∞`、逐級 slice × 單價）。
- 純邏輯 `ApplyTiers` / `BuildTierRows` / `SelectPlanForDate` / `ValidatePlan` 為 public static，單元測試鎖規則：
  `ScadaEngine.Tests/GasMeter/GasCostServiceTests.cs`（級距交界、0 度、超大量、小數、空白 seed 範本）、`GasTariffServiceTests.cs`（驗證 + seed 解析 + 版本選擇）。

## 5. 氣費報表（/GasCostReport）

- 選迴路 + 起訖月（期別區間）→ 每期一列：期別、用氣量（m³）、套用方案（含生效日）、氣費，可展開級距明細。
- **已刪除（兩月一期）的期別不會出現** — 查一整年得 6 列。
- 切換歷史期別時採用**該期起日生效**的方案版本。
- Excel 匯出：`GasCostReportExcelExporter`（ClosedXML，i18n resx）；資料不完整期別於期別欄加「*」註記。

## 6. EMS 氣費狀態卡（GasCost）

- 預設樹根迴路（全廠），可下拉切換迴路；顯示本期（`GetCurrentPeriodAsync`，自動跳過已刪除期別）用氣量、各級距 slice 明細、流動氣費合計。
- 未設定方案（config 無方案）→ 卡片顯示「尚未設定氣費方案」引導至 `/GasTariffSetting`。
- API：`GET /EMS/api/gas-cost?circuitId=`。
